## 一、这个项目到底需要哪些知识？

对着项目源码反推，需要 6 块知识：

```
                    ┌────────────────────────────┐
                    │      自瞄 = 感知 + 估计 + 决策 + 执行      │
                    └────────────────────────────┘
   感知 ←── C++进阶 + OpenCV + 神经网络/YOLO
   估计 ←── 线性代数/坐标变换 + 卡尔曼滤波
   决策 ←── 控制基础(PID/弹道/MPC) + 状态机
   执行 ←── 通信(串口/CAN) + 多线程 + Linux/CMake
```

好消息：**没有任何一块需要天赋，全是可以按周学完的**。坏消息：每一块都要动手写代码才能真会。

总计约 3 个月（课余）。**阶段 1 的灯条检测 demo 是最重要的一关**——做完它你就理解了传统视觉 70% 的套路。

### 灯条检测 demo 具体要求

拿一张 RM 装甲板照片（官网/开源仓库都有），用 OpenCV 完成：

1. `cvtColor` 灰度化 → `threshold` 二值化 → `findContours` 找轮廓
2. `minAreaRect` 拟合灯条，打印每根灯条的长宽比和角度
3. 筛掉 ratio < 3 的"假灯条"，把剩下的画框显示出来
4. 加分：把两根灯条配对成装甲板，画在图上

做完这个再对照 [视觉/02-传统检测器](/posts/autoaim-02-traditional-detector)，你会发现项目代码就是把你的 demo 参数化、加固了十倍。

## 三、每个阶段的过关自测

### 阶段 0（C++/Linux）自测
- `unique_ptr` 和裸指针的区别？为什么项目用 `unique_ptr<YOLOBase>`？
- `std::mutex` + `condition_variable` 解决什么问题？
- 两个线程同时写一个 `int` 会发生什么？怎么解决？
- Linux 下怎么给 `/dev/ttyACM0` 加权限？

### 阶段 1（数学/OpenCV）自测
- 旋转矩阵为什么是正交的？R·Rᵀ = ?
- 相机内参 fx, fy, cx, cy 各是什么意思？
- solvePnP 的输入输出是什么？为什么装甲板 4 个点就够？
- `minAreaRect` 返回什么？怎么从它得到灯条端点？

### 阶段 2（滤波）自测
- 为什么要滤波而不是直接用测量值？
- Q 调大意味着更信测量还是更信模型？R 呢？
- EKF 和 KF 的唯一区别是什么？
- 为什么角度状态要 limit_rad 到 ±π？

### 阶段 3（控制）自测
- PID 三个项各自的物理意义？D 项为什么用"微分先行"？
- 打移动目标为什么不能直接瞄当前位置？（飞行时间提前量）
- MPC 和 PID 的本质区别是什么？

### 阶段 4（YOLO）自测
- softmax 输出的含义？置信度 0.7 阈值过滤的是什么？
- NMS 在解决什么问题？
- pt → onnx → IR(.xml/.bin) 转换链是怎么回事？

## 五、心态建议

1. **先跑通，再读懂，最后改对**。每接触一个新模块，先编译运行对应的 `tests/*_test`，看现象，再回头读代码；
2. **别怕数学**。项目里的数学全部是本科二年级范围内：线代、概率、一元二次方程。推导看不懂就先记住结论和直觉，用起来再回头补；
3. **每篇笔记里的"结合项目"小节是钥匙**——把抽象知识和具体代码挂钩，比刷教材快得多；
4. 卡住超过半天就去找人问或者把问题写下来继续往下走，不要在单个知识点上死磕。
