## 1. 反馈控制的最小概念

你要云台转到 30°，现在在 25°——差 5°。控制器的工作：**把误差变成执行指令，并让误差趋近 0**。

```
        目标角
          │
          ▼
   ┌──────────┐   误差 e    ┌──────────┐    控制量    ┌────────┐
   │  目标设定 │───────────►│ 控制器    │───────────►│ 电机    │──┐
   └──────────┘             └──────────┘             └────────┘  │
          ▲                                                      │
          │                ┌──────────┐                          │
          └────────────────│ 编码器测角 │◄─────────────────────────┘
                           └──────────┘      反馈
```

## 2. PID：三个项的物理含义

```
u(t) = Kp·e + Ki·∫e·dt + Kd·de/dt
```

| 项 | 直觉 | 比喻（开车对准车道） |
|---|---|---|
| **P 比例** | 误差大就使劲打 | 偏得多方向盘打得多 |
| **I 积分** | 累积小误差，消除稳态偏差 | 一直偏一点点，慢慢多打一点 |
| **D 微分** | 误差变化快就提前刹车 | 接近车道中心时回方向盘防冲过头 |

项目实现（tools/pid.cpp）里的两个工程细节，比公式更重要：

1. **角度模式**：yaw 是循环量（359° 和 1° 只差 2°），误差和微分都要过 `limit_rad`；
2. **微分先行**：D 项对**测量值**微分而不是对误差——目标角突变时不会产生巨大的 D 冲击；
3. **积分限幅**（抗饱和）：`iout = clip(iout + e·dt·ki, ±max_iout)`——防止长时间大误差把积分撑爆。

```cpp
float e  = angular_ ? limit_rad(set − fdb) : (set − fdb);
float de = angular_ ? limit_rad(last_fdb_ − fdb) : (last_fdb_ − fdb);  // 微分先行
iout = clip(iout + e·dt·ki, ±max_iout);
```

调参口诀：先 P 后 D 再 I；P 大震荡、D 大抖动、I 大超调。

## 3. 状态空间模型（MPC 的语言）

把系统写成"状态如何演化"的矩阵方程：

```
x_{k+1} = A·x_k + B·u_k
```

**双积分器**（云台的简化模型——角度是角速度的积分，角速度是角加速度的积分）：

```
状态 x = [角度; 角速度]，控制 u = 角加速度
A = [[1, dt],      B = [[0],
     [0, 1]]            [dt]]

angle_{k+1} = angle_k + dt·ω_k
ω_{k+1}     = ω_k + dt·α_k
```

这就是 planner.cpp:117-119 里的 A、B——**云台被建模为"角加速度指令驱动"的系统**。

## 4. MPC：滚动优化的思想

PID 只看当前误差；MPC 看的是**未来一整段轨迹**：

```
1. 给我一条未来 1s 的参考轨迹（想要云台每个 10ms 时刻在哪、角速度多少）
2. 在"角加速度受限"的约束下，找一条尽量贴近参考的可行轨迹
3. 只执行第一步，下一周期重新算（滚动时域）
```

数学形式（planner.cpp:110-154）：

```
min  Σ ‖x_k − Xref_k‖²_Q  +  ‖u_k‖²_R
约束  |u| ≤ max_acc          （yaw 50 rad/s²，pitch 100 rad/s²）
```

- **Q 大** → 贴轨迹优先；**R 大** → 平滑省力优先；
- 约束让 MPC 天生"知道自己的极限"——装甲板切换时提前减速，这是 PID 做不到的。

求解用什么？ADMM 迭代（admm.cpp）——本科阶段只需知道：**预计算（Riccati）+ 每帧 10 次轻量迭代 = 实时可行**。TinyMPC 的"tiny"就是指这个。

### MPC vs PID 的本质区别（面试也能答）

| | PID | MPC |
|---|---|---|
| 看什么 | 当前误差 | 未来整段参考 |
| 约束 | 没有（靠限幅硬顶） | 显式建模（加速度受限） |
| 输出 | 一个控制量 | 轨迹 + 速度/加速度前馈 |
| 计算量 | 极小 | 大（但 TinyMPC 已优化到 10ms 内） |

## 5. 弹道解算：一元二次方程就够了

真空抛物线（项目实际用的，trajectory.cpp）：

```
d = v0·cosθ·t          （水平匀速）
h = v0·sinθ·t − ½·g·t²  （竖直匀加速）
```

消去 t（令 T=tanθ，用 1/cos²θ=1+T²）：

```
h = d·T − (g·d²/2v0²)·(1+T²)
→ a·T² + b·T + c = 0,  a = g·d²/(2v0²),  b = −d,  c = a+h
→ T = (−b ± √(b²−4ac)) / 2a
```

两个解 = **高抛弹道 / 低伸弹道**，取飞行时间短的（低伸）。判别式 <0 = 目标超出射程。

### 为什么需要"迭代"？——移动目标的提前量

打移动目标时：你瞄的位置取决于弹丸飞行时间，而飞行时间又取决于你瞄的位置。循环！

```
fly_time = T( aim_point(now + fly_time) )
```

解法：**不动点迭代**（aimer.cpp:78-116）——先猜一个 fly_time，算瞄准点和新 fly_time，反复替换，直到变化 <0.001s（≤10 次）。这是数值计算里最朴素也最常用的思想。

## 6. 开火决策：不是"瞄准就打"

Shooter 的 5 条判据（shooter.cpp:19-41）全部满足才开火：

```
① 自瞄接管且有目标          ② 距离>2m 用 2° 容差，近距用 3°
③ 本次命令与上次差 < 2×容差   （防目标切换瞬间"甩枪走火"）
④ 云台实际角跟上上次命令      （用 last_command_——子弹打的是上一拍的方向）
⑤ 瞄准点有效
```

MPC 管线的开火判据更优雅：**MPC 预测状态与理想参考在 +20ms 处的联合误差 < 0.003 rad**——"按我的动力学，20ms 内能贴上理想方向，才打"。

## 7. 状态机（决策的骨架）

Tracker 用有限状态机管理目标生死（tracker.cpp:180-229）：

```
lost ──连续5帧检测到──► detecting ──► tracking ──丢≤15帧──► temp_lost ──找回──► tracking
                           │                        │
                           └──一次失败回 lost        └──丢超15帧回 lost
（switching：全向感知发现更高优先级目标，云台先转过去的中间态）
```

**状态机 = 把"什么条件下允许什么行为"写清楚**。设计决策类代码时先画状态转移图，再写代码，比边写边想要稳得多。
